The Problem
worth solving

StellarIO's team was drowning in raw data. They had powerful infrastructure producing thousands of events per second — but no way to see it. Engineers lived in terminal windows, product managers printed CSV exports, and decisions were made on data that was already hours old.

They needed a single source of truth. Something fast enough to keep up with their infrastructure, rich enough to replace five different tools, and clear enough that a non-technical stakeholder could read it at a glance.

"We didn't need more data. We needed to finally understand the data we already had."

Orbital was built to solve exactly that — a real-time analytics dashboard with WebGL-powered visualisations, live WebSocket feeds, and a component architecture that makes dense data feel approachable and even beautiful.

Challenges

Hard problems,
elegant solutions

⚡
60fps at Scale
Rendering 2,000+ live data points without dropping frames. Solved by moving all visualisations off the main thread into WebGL via Three.js, with a custom instanced geometry system.
🌊
Real-time Data
WebSocket connections handling 18k events/second without memory leaks. Built a ring-buffer data structure that caps memory usage while maintaining a 60-second rolling window.
🎯
Information Density
Showing complex data without cognitive overload. Designed a progressive disclosure system — overview first, drill-down on demand — with a carefully tuned visual hierarchy using contrast and spacing.

Project Timeline

3 months,
zero scope creep

Week 1–2
Discovery & Architecture
Stakeholder interviews, data audit, and technical architecture decisions. Chose WebSocket over polling, Three.js for 3D, and established the ring-buffer pattern for live data.
Week 3–4
Design System & Prototyping
Dark theme design token system in Figma, responsive grid, chart component library with 12 chart types. High-fidelity prototype validated with 6 users before any code was written.
Week 5–8
Core Build
WebSocket infrastructure, React component build, WebGL visualisation engine, and D3 chart integration. Performance benchmarked continuously — no regressions past 55fps.
Week 9–10
Alert Engine & Integrations
Configurable rule engine with Slack/email notifications. Integrated with the client's existing Datadog and PagerDuty setup for zero-disruption alerting workflow.
Week 11–12
Testing, Polish & Launch
Full Playwright E2E suite, accessibility audit (WCAG AA), load testing at 10× expected traffic, and a zero-downtime staged rollout to the full team.
